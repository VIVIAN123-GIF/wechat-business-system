## 二、建议完成

### 4. 整理最终项目说明

最终报告或项目说明中，建议明确写出：

- 系统采用 C/S 架构
- 服务端使用 C++、SQLite、TCP、多线程
- 客户端使用控制台 UI
- 促销采用策略 + 装饰 + 工厂
- 使用事务和原子 SQL 防止超卖
- 使用 Token 鉴权和 SHA-256 密码摘要
- 结算目前是同步应答
- 支付是模拟支付，不接入真实支付平台

### 5. 补充 UML 或结构图

至少建议准备：

- 系统总体架构图
- 客户端/服务端时序图
- 促销策略类图
- 数据库 ER 图
- 结算与库存扣减流程图

这些比继续增加普通业务功能更有价值。

### 6. 做一次人工操作检查

除了自动化测试，还应手动确认：

- 客户端中文显示正常
- 三套主题切换正常
- 商品价格显示正确
- 订单状态和退货状态显示正确
- 普通用户不能审核退货
- 未登录用户不能访问业务接口
- 购物车为空时不能结算
