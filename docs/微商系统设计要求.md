### 一、项目背景与核心定位
- **系统名称**：微商系统
- **行业参照**：拼多多、云极品（*注：原文如此，可能为特定平台*）、有赞、微店等移动端电商APP。
- **业务本质**：社交 + 零售。
- **常见运营模式**：引流 → 吸粉 → 交易。
- **功能对标**：类似手机淘宝、京东的核心购物流程，但聚焦于社交零售场景。

---

### 二、系统架构选型（两种框架对比）
- **C/S 框架（客户端/服务器）**
  - 服务器和客户端均需安装独立程序。
  - 采用 MVC 模式（UI界面、业务层、持久层分离）。
  - 数据库通过服务端持久层管理。
  - 通信方式：TCP/IP 协议。
- **B/S 框架（浏览器/服务器）**
  - 仅需部署服务器端程序，用户通过浏览器访问。
  - 采用 MVC 模式。
  - 通信方式：HTTP 协议，依托 Web 容器。

---

### 三、系统功能需求（核心业务模块）
- **商品浏览**：查看产品列表。
- **购物车管理**：添加、删除商品。
- **促销策略（混合策略）**：
  - 需使用**反射 + 策略模式 + 装饰模式**等设计模式实现灵活促销。
  - 具体促销形式包括：统一打折、阶梯折扣（如第2件9折、第3件8折或免单）、直降降价、优惠券抵扣。
- **结算功能**：订单金额计算与支付处理。
- **售后服务**：支持退货等售后流程。
- **UI 展示**：支持不同风格的界面选择（皮肤切换）。

### 四、系统性能与设计要求
- **高并发处理**：需考虑类似“双9.9”大促场景下的流量冲击。
- **互斥与资源竞争**：处理限量商品（如爱马仕、Costco模式）时的库存扣减，确保数据一致性。
- **通信模式**：支持同步通信或异步通信。
- **架构柔性**：分层设计需体现“柔性”（可扩展性、可维护性）。
- **开发流程**：严格遵循软件工程生命周期（需求分析 → 系统设计 → 代码实现）。

### 五、系统详细架构分层
| 层级 | 客户端职责 | 服务端职责 |
| :--- | :--- | :--- |
| **UI层** | 商品展示、用户交互、购物车/结算/折扣/售后界面 | 交易结果展示、数据统计分析界面（如Web服务） |
| **业务层** | 发起交易请求、预处理交易 | 完成交易逻辑、执行促销策略（支持异步通信，可采用观察者模式处理交易；引入消息队列） |

- **跨语言支持**：服务端可用 Java，客户端可用 C++，实现跨语言通信。

### 六、TCP/IP 通信协议定义
- **协议编码**：双向通信（请求 + 应答），可设计为定长或不定长报文。
- **协议示例（业务码）**：
  - `1001`：商品展示请求。
  - `10020001`：将 1 号商品加入购物车请求。
  - `1003`：结算当前购物车请求。
  - `20020001`：1号商品加入购物车成功应答。
  - `2003`：结算成功应答。
