2. 客户端 / 服务端时序图

以结算（协议码 1030）为例的完整请求-响应链路：接入线程只负责收包入队，Worker 线程出队后经 HandlerFactory 分发到 CheckoutHandler，内部完成鉴权 → 事务 → 原子扣减 → 促销链 → 落库 → 提交 → 观察者广播。

order_no UNIQUE 冲突重试≤3次 OR-->>H: 成功 H->>DB: COMMIT H->>H: OrderEventBus.notifyOrderCreated 观察者广播 H-->>W: resp={order_id,order_no,original,discount,final,promo_desc} W->>CH: send(2030, resp) CH-->>TC: TCP 响应报文 TC-->>CC: receiveResponse → code=2030 CC-->>U: 渲染结算结果 Note over H,DB: 任一步失败 → ROLLBACK → 返回 4001（业务错误码）

3. 促销策略类图

IPromotion 为策略接口；四种具体策略（打折/直降/满减/阶梯折扣）；PromotionDecorator 抽象装饰器派生出 ExtraDiscountDecorator（VIP 折上折）与 CompositeDecorator（促销叠加）；PromotionFactory 按数据库记录创建策略，PromoChainBuilder 用装饰模式层层包装成链。

4. 数据库 ER 图

依据 database/schema.sql 实际表结构。六张表：users / products / orders / order_items / returns / promotions。金额全部以整数分存储；order_items 保存商品名称与单价快照。

注：order_items.product_id 为逻辑引用，schema 中未建立外键约束（购买后商品可下架/删除，快照保证订单不可变）。
