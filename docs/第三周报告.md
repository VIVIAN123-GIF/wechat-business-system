##### 3.1 客户端核心类设计

**① TcpClient（通信封装类）**

```cpp
#pragma once
#include <winsock2.h>
#include <string>
#include <vector>

class TcpClient {
private:
    SOCKET sockfd;
    std::string serverIp;
    int serverPort;
    bool isConnected;

public:
    TcpClient(const std::string& ip = "127.0.0.1", int port = 8888);
    ~TcpClient();

    // 禁止拷贝
    TcpClient(const TcpClient&) = delete;
    TcpClient& operator=(const TcpClient&) = delete;

    bool connect();
    void disconnect();
    bool isConnected() const { return isConnected; }

    // 发送数据（自动添加协议头）
    bool sendRequest(int protocolCode, const std::string& jsonBody);

    // 接收数据（自动解析协议头，处理粘包）
    bool receiveResponse(int& outProtocolCode, std::string& outJsonBody, int timeoutSec = 5);

private:
    bool sendRaw(const char* data, int len);
    bool recvRaw(char* buffer, int len);
};
```

**设计要点**：RAII管理Socket资源，析构自动`closesocket`；`recvRaw`循环读取确保读满指定字节；禁止拷贝防止重复关闭。

**② ProtocolEncoder（协议编解码器）**

```cpp
#pragma once
#include <string>
#include <cstdint>

#pragma pack(push, 1)
struct ProtocolHeader {
    uint32_t magic;      // 魔术字 0x4D495F53 ("MI_S")
    uint32_t version;    // 版本号 0x00000001
    uint32_t code;       // 协议码
    uint32_t length;     // 数据体长度（不含头）
};
#pragma pack(pop)

class ProtocolEncoder {
public:
    static std::vector<char> encode(uint32_t code, const std::string& jsonBody);
    static bool decode(const std::vector<char>& buffer, 
                       uint32_t& outCode, 
                       std::string& outJsonBody);
    static uint32_t getHeaderSize() { return sizeof(ProtocolHeader); }
};
```
**设计要点**：使用`#pragma pack`确保结构体无内存对齐空隙；头部添加`magic`和`version`字段为未来扩展预留空间。

**② TaskQueue（任务队列 + 观察者模式目标）**

```cpp
#pragma once
#include <queue>
#include <mutex>
#include <condition_variable>
#include <memory>

struct Task {
    SOCKET clientFd;
    uint32_t protocolCode;
    std::string jsonBody;
    uint64_t timestamp;  // 用于超时管理
};

class TaskQueue {
private:
    std::queue<Task> queue;
    std::mutex mtx;
    std::condition_variable cond;
    std::atomic<bool> shutdown;

public:
    static TaskQueue& getInstance();  // 单例

    void push(const Task& task);
    Task pop();  // 阻塞等待
    bool tryPop(Task& outTask, int timeoutMs = 100);
    size_t size() const;
    void setShutdown(bool flag);
};
```
**设计要点**：使用单例确保全局唯一的任务队列；`pop()`通过`condition_variable`实现阻塞等待（观察者模式的目标对象）。

```cpp
    int id;
    double discountRate;  // 0.8 表示8折
public:
    DiscountPromotion(int id, double rate) : id(id), discountRate(rate) {}
    double apply(double price, int quantity) override { 
        return price * quantity * discountRate; 
    }
    std::string getDescription() const override { 
        return "打" + std::to_string((int)(discountRate * 100)) + "折"; 
    }
    int getId() const override { return id; }
};

class CouponPromotion : public IPromotion {
private:
    int id;
    double threshold;   // 满多少
    double reduce;      // 减多少
public:
    CouponPromotion(int id, double t, double r) : id(id), threshold(t), reduce(r) {}
    double apply(double price, int quantity) override {
        double total = price * quantity;
        return total >= threshold ? total - reduce : total;
    }
    // ...
};

// 装饰器抽象基类（关键）
class PromotionDecorator : public IPromotion {
protected:
    std::unique_ptr<IPromotion> wrapped;  // 被装饰的策略
public:
    explicit PromotionDecorator(std::unique_ptr<IPromotion> p) : wrapped(std::move(p)) {}
    virtual ~PromotionDecorator() = default;
    double apply(double price, int quantity) override {
        return wrapped ? wrapped->apply(price, quantity) : price * quantity;
    }
    std::string getDescription() const override {
        return wrapped ? wrapped->getDescription() : "";
    }
    int getId() const override { return wrapped ? wrapped->getId() : -1; }
};

// 具体装饰器：先执行原始策略，再额外打9折（叠加）
class ExtraDiscountDecorator : public PromotionDecorator {
private:
    double extraRate;
public:
    ExtraDiscountDecorator(std::unique_ptr<IPromotion> p, double rate) 
        : PromotionDecorator(std::move(p)), extraRate(rate) {}
    double apply(double price, int quantity) override {
        double base = PromotionDecorator::apply(price, quantity);
        return base * extraRate;  // 层层包装
    }
    std::string getDescription() const override {
        return PromotionDecorator::getDescription() + " + 额外" + 
               std::to_string((int)(extraRate * 100)) + "折";
    }
};
```

**ORM映射策略（对象↔关系）** ：

| 实体类 | 对应表 | 映射方式 |
|--------|--------|----------|
| `User` | users | 直接映射，level字段区分不同派生类（多态在代码层实现） |

**关键设计决策**：
1. **订单明细使用快照（冗余存储）** ：商品信息（价格、名称）可能会调整，但历史订单应该保持购买时的状态。因此`order_items`中的`product_name`和`price`是下单时的副本，而非实时关联`products`表。
2. **外键级联删除**：删除用户时自动级联删除其订单，保证数据一致性。
3. **业务订单号**：`order_no`使用`MS`+`yyyyMMdd`+`序号`格式，便于人工识别和客服查询。

```cpp
// 服务端接收循环（伪代码）
bool recvFullPacket(SOCKET fd, ProtocolHeader& header, std::string& body) {
    char headBuf[sizeof(ProtocolHeader)];
    if (!recvExact(fd, headBuf, sizeof(ProtocolHeader))) return false;
    header = parseHeader(headBuf);

    // 根据头部长度读取body（防止半包）
    body.resize(header.length);
    if (header.length > 0) {
        if (!recvExact(fd, body.data(), header.length)) return false;
    }
    return true;
}

bool recvExact(SOCKET fd, char* buffer, int len) {
    int received = 0;
    while (received < len) {
        int ret = recv(fd, buffer + received, len - received, 0);
        if (ret <= 0) return false;  // 连接关闭或错误
        received += ret;
    }
    return true;
}
```

#### 2.1 与概要设计相比的调整

经过第二周（概要设计）到第三周（详细设计）的深入思考，我对部分设计进行了**修正和细化**，但没有推翻整体架构：

**调整一：通信模式从“纯同步”细化为“同步+异步混合”**

| 层面 | 概要设计（第二周） | 详细设计（第三周，修正后） | 调整原因 |

**调整三：促销策略的“反射”实现方式**

概要设计中提到“反射+策略+装饰等模式”。由于**C++原生不支持反射**（与Java不同），本周对实现方式做了调整：

- 这样实现了“通过配置动态加载促销”的效果，等价于反射的“运行时类型识别”

**调整四：UI设计从“抽象接口”细化为“两种具体风格”**

#### 4.2 当前困难的部分及应对策略

**困难一：Windows下Socket编程的具体API细节**

| 具体困难 | 详细描述 |
|----------|----------|
| Winsock初始化 | `WSAStartup`的版本选择及清理时机 |
| 非阻塞与超时 | `select`或`setsockopt`设置`SO_RCVTIMEO`的具体参数 |
| 多线程下的Socket管理 | 一个客户端连接对应一个线程，线程安全地关闭Socket |
| 跨平台兼容性 | 虽然只在Windows测试，但`closesocket` vs `close`的区别 |

**应对策略**：
- 参考《TCP/IP网络编程》（尹圣雨）的Winsock示例代码
- 使用RAII封装`WSAInitGuard`类，确保`WSACleanup`自动调用
- 每个`TcpClient`连接使用独立的`SOCKET`，不跨线程传递
- 利用`std::thread`和`std::jthread`管理客户端线程生命周期

**困难二：线程安全的库存扣减（防止超卖）**

| 具体困难 | 详细描述 |
|----------|----------|
| 并发场景下的原子操作 | 两个线程同时读取库存、扣减库存，如何保证一致性 |
| 数据库锁 vs 内存锁 | 是在内存中加锁（`std::mutex`）还是在SQL层面加锁（`BEGIN TRANSACTION`） |
| 死锁风险 | 多个商品同时扣减时，加锁顺序如何统一 |

**应对策略**：
- **两级锁策略**：
  1. 内存级：使用`std::mutex`保护`ProductRepository`的`stockCache`映射
  2. 数据库级：使用`BEGIN IMMEDIATE TRANSACTION` + `UPDATE products SET stock = stock - ? WHERE id = ? AND stock >= ?`
- 统一加锁顺序：按`productId`升序加锁，防止死锁
- 使用`std::lock_guard`自动释放锁，防止异常导致锁未释放

**困难三：C++与SQLite的集成调试**

| 具体困难 | 详细描述 |
|----------|----------|
| 错误信息获取 | `sqlite3_errmsg(db)`返回的字符串生命周期管理 |
| 内存泄漏 | 每次`sqlite3_prepare_v2`后必须`sqlite3_finalize` |
| 二进制数据（BLOB） | 本系统暂不使用BLOB，仅处理文本和数字，降低难度 |

**应对策略**：
- 封装`SQLiteHelper`类，在析构函数中自动`finalize`所有stmt
- 使用`std::shared_ptr<sqlite3_stmt>`配合自定义Deleter
- 编写测试用例，在纯C++环境下先测试SQLiteHelper再集成到服务端

**困难四：异步通知的客户端接收**

课件要求的异步通信模式中，结算请求是异步的——客户端发起1030后，服务端立即返回2030（处理中），随后通过2031异步推送结算结果。但TCP是双向的，客户端需要**同时**维持发送和接收能力。如何让客户端既能主动发请求，又能随时接收服务端的异步推送？

**应对策略**：
- **双线程模型**：客户端主线程负责UI交互和发送请求；单独的`receiverThread`持续阻塞`recv`，接收到2031时通过回调函数或观察者模式通知主线程更新UI。
- 或采用**非阻塞IO + select**实现单线程事件驱动。
- 权衡后选择**双线程 + 线程安全队列**方案：接收线程收到消息后放入`incomingQueue`，主循环每次迭代检查队列并处理。
