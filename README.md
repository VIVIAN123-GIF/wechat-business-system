# 微商系统 - 面向对象课程设计

基于 **C/S 架构**的社交零售模拟系统，实现商品浏览、购物车、混合促销策略（策略+装饰+工厂）、结算（事务+防超卖）、订单查询、售后退货等功能。

## 技术栈

- **语言/标准**：C++17（MinGW-W64 8.1.0 实测通过）
- **服务端**：Winsock2 + 多线程（Acceptor + 每客户端收发线程 + WorkerPool 线程池）+ SQLite（嵌入式，自动建表初始化）
- **客户端**：控制台交互（UTF-8），策略模式双 UI 风格（极简/详细）
- **通信**：自定义 TCP 应用层协议（16 字节定长头 + JSON 变长体，长度前缀法防粘包）；登录会话 token 鉴权 + 密码 SHA-256 摘要传输/存储
- **设计模式**：策略（促销/UI）、装饰（促销叠加）、工厂（Handler/促销）、命令（Handler）、观察者（订单事件）、单例（TaskQueue）；TaskQueue 采用生产者—消费者模型
- **并发**：生产者-消费者消息队列、互斥锁 + SQL 原子扣减双保险防超卖、事务（BEGIN IMMEDIATE）
- **金额**：全链路整数分（int cents）存储与传输，促销内部 double 计算后 round 到分，彻底消除浮点误差
- **构建**：同时支持 build.bat（MinGW 命令行）与 CMake（`cmake -B build && cmake --build build`）

## 快速开始

### 1. 编译（需要 MinGW-W64 8.1+，含 gcc/g++）

```bat
build.bat
```

### 2. 启动服务端

```bat
build\server.exe
```

首次启动自动创建 `ms.db` 并初始化种子数据（3 用户 / 6 商品 / 6 促销，含阶梯折扣）。按 `q` 回车停止。

### 3. 启动客户端（另开终端）

```bat
build\client.exe
```

### 4. 集成测试（需先启动服务端）

```bat
build\test_client.exe   # 需先单独编译：见 build.bat 注释或 test/README
```

## 设计亮点

- **UI 皮肤主题切换（抽象工厂）**：`UIFactory` 抽象工厂按"主题色族"生产界面产品——`BlueThemeFactory/GreenThemeFactory/PinkThemeFactory` 各产出极简/详细两款风格渲染器；ANSI 颜色码实现 3 套配色（蓝/绿/粉），终端下依然有效；客户端"一键换肤"= 切换具体工厂
- **混合促销**：策略模式定义打折/直降/满减/阶梯折扣算法族，装饰器按选择顺序叠加（如"第2件9折，再满200减30"），工厂从数据库配置创建对象；新增算法类型需要补充子类和工厂映射，但结算主流程保持稳定
- **阶梯折扣**：`TierDiscountPromotion` 按"同一商品购买数量"分档计价（第2件9折、第3件8折、第N件免单），通过明细感知接口 `applyToItems` 与总额类促销（满减/打折）自由叠加，超出最高档按末档折扣延续
- **销售数据统计**：服务端 UI 层提供数据统计分析界面（协议 1060/2060）——按日销售趋势、热销商品排行、用户贡献排行、汇总指标（订单数/实收/优惠/客单价/退货数），支持选时间区间（最近 N 天）与选统计对象（指定商品/用户）；服务端启动时同步输出运营数据概览
- **商品搜索**：协议 1005/2005，按名称/分类/描述 `LIKE` 模糊查询（`%`/`_` 通配符已转义防注入），复用商品列表渲染与加购流程，对齐"手机淘宝/京东核心购物流程"
- **联系客服（社交）**：协议 1065/2065，客户端发消息 → 服务端控制台回显（客服侧可见）+ 自动应答，无状态实现命中"社交+零售"定位而不引入长连接管理；消息长度上限 500 字防日志注入
- **会话鉴权**：登录（1006）成功返回会话 token（SessionManager 单例管理，绑定 user_id）；加购/结算/订单/退货/统计/客服等业务请求统一校验 token，未登录返回 4002——杜绝伪造 user_id 冒用他人身份（集成测试验证）
- **密码摘要**：`common/SHA256.h` 按固定前缀、用户名和密码计算 SHA-256 摘要，客户端/服务端共用，存储与传输均不使用明文；启动时自动迁移存量明文密码。生产环境仍需 TLS 和专用密码哈希算法
- **售后闭环**：退货申请原子化（`UPDATE ... WHERE status IN(...)` 防重复提交）+ 记录订单原状态 → 管理员审核（1080/2080）通过时**回补库存**并置订单"已取消"，拒绝时恢复原状态；客户端提供"退货进度"与"退货审核"入口，订单列表显示中文状态与退货标记
- **防超卖**：`std::mutex` 内存锁 + `UPDATE ... SET stock=stock-? WHERE stock>=?` 数据库原子扣减 + 事务回滚；8 个独立待支付订单并发抢 1 件限量库存时仅 1 单支付成功
- **异步与观察者**：TaskQueue 用生产者—消费者模型解耦接入和业务；订单创建后 OrderEventBus 向 OrderEventListener 广播事件
- **粘包处理**：长度前缀法，先读满 16 字节头再按 Length 循环 `recv`
- **整数分金额**：价格/订单/明细全部用 int（分）存储传输，客户端 /100 显示元；VIP 折上折 0.95 经 round 精确到分，无 0.001 容差兜底
- **分层测试**：集成测试走真实 socket（79 项断言，覆盖业务链路、互斥促销和独立订单并发支付），单元测试离线验证 SHA-256 已知向量与促销引擎（26 项断言）
- **工程化收口**：订单/退货状态统一为 `OrderStatus`/`ReturnStatus` 枚举（消除魔法数字）；`recvExact`/`recvFullPacket` 下沉为 `common/NetUtil.h` 公共实现（服务端/客户端/测试三处共用）；建表与种子数据外部化为 `database/schema.sql`+`init_data.sql`，代码不再内嵌 DDL，老库启动自动迁移
